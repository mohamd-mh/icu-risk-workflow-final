Information System Context

Stakeholders

The ICU Risk Workflow supports several direct and indirect stakeholders in an academic clinical information-system prototype.

AI Methodology
Clinical Reviewer

Clinical Reviewer

Role: Reviews ICU stay summaries and documents local review status.

Need: Clear risk outputs, explanations, measurements, and audit trail.

User story: As a clinical reviewer, I want to compare baseline, multi-agent, and AI outputs so that I can document a structured case review.

Shift Workflow

ICU Nurse / Shift Reviewer

Role: Uses the worklist to scan ICU stays during a shift review workflow.

Need: A readable dashboard, filters, and priority indicators.

User story: As a shift reviewer, I want to filter cases by risk and data quality so that I can focus review attention efficiently.

Operations

Department Manager

Role: Monitors review volume, follow-up status, and workflow coverage.

Need: Aggregate counts, queue visibility, and review status summaries.

User story: As a department manager, I want a dashboard view so that I can understand review workload and unresolved follow-up items.

Analysis

Data Analyst / Researcher

Role: Evaluates model behavior, metrics, feature availability, and comparison outputs.

Need: Model methodology, evaluation results, and transparent feature handling.

User story: As a researcher, I want to inspect model metrics and input features so that I can evaluate the prototype design.

Administration

System Administrator

Role: Runs the Flask app locally and checks project files and generated artifacts.

Need: Clear run instructions, local JSON storage, and validation checks.

User story: As a system administrator, I want documented routes and storage files so that I can run and verify the prototype.

Academic Review

Academic Evaluator

Role: Reviews whether the project works as a research website and software artifact.

Need: Clear navigation, methodology, stakeholder context, and working pages.

User story: As an academic evaluator, I want to see the research explanation and runnable system so that I can assess the final deliverable.

Indirect Stakeholder

Indirect Patient Stakeholder

Role: Represents the people whose de-identified ICU records motivate safer information-system design.

Need: Responsible data use, clear limitations, and no direct clinical claims.

User story: As an indirect patient stakeholder, I want the prototype to use de-identified data responsibly so that academic review does not overstate clinical use.
