Pipeline

Review Workflow: From Data to Review Support

  1. A dataset case is loaded or a manual case is entered.
  2. Values are aligned to the trained model input schema.
  3. Missing values are handled by the preprocessing/model pipeline.
  4. The supervised ML model outputs a probability.
  5. The probability is mapped to Low / Medium / High risk.
  6. Explainability shows model-important features.
  7. Similar-case retrieval, clustering, anomaly detection, and uncertainty estimation add review context.
  8. The ICU Quality & Patient Safety Coordinator records status, priority, notes, and audit history.
Methods

Real AI Methods Used

  • Supervised ML risk prediction
  • Explainable AI using saved model feature importance
  • KNN similar-case retrieval
  • KMeans clustering
  • IsolationForest anomaly detection
  • Uncertainty estimation using probability, entropy, threshold distance, and data quality
  • Optional live generative AI only when LLM_API_KEY is configured

The implemented prototype is not a full autonomous AutoGen-style multi-agent negotiation system. It uses a modular sequence of specialized components for prediction, verification, explainability, similarity, anomaly detection, uncertainty estimation, and review documentation.

Related Work

Scientific Basis / Related Work

MIMIC-style ICU prediction benchmarks commonly study in-hospital mortality prediction, decompensation detection, length-of-stay prediction, and phenotype classification. MIMIC processing frameworks emphasize standardized extraction, imputation, and reproducible preprocessing.

ICU severity scoring systems such as APACHE II and SOFA use physiological, laboratory, organ-function, age, and admission-context variables. This supports the use of these feature families as model inputs, but this project uses those ideas as academic and software-engineering grounding, not as clinical validation.

Reference labels: Harutyunyan et al., 2019, MIMIC-III Benchmarks; MIMIC-Extract, 2019; APACHE II; SOFA.
