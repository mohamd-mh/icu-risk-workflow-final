User Guide

AI-Assisted ICU Quality Review Workbench

Practical guide for an ICU Quality & Patient Safety Coordinator using the local academic workbench.

Open Review Queue

What the Coordinator Does

The coordinator reviews prioritized cases, assigns status and priority, records ownership, adds notes, checks audit history, and archives items when review documentation is complete.

Dashboard

The Dashboard is the first screen. It shows total ICU cases, active review items, high AI risk cases, SIRS-positive cases, follow-up work, low-confidence or missing-data cases, risk/status distributions, recent activity, and quick actions.

Review Queue

The Review Queue is the main workspace. Use filters for status, priority, AI risk, SIRS screening, source, coordinator, and search. Open a Case Safety Profile, add notes, update ownership/status/priority, and archive completed items.

Case Library

The Case Library browses the processed ICU feature dataset with pagination. Search by ICU stay ID, filter by AI risk or SIRS screening, open a Case Safety Profile, or add a dataset case to the Review Queue.

Create Review Ticket

Manual cases are local software submissions for AI-supported quality review. The optional Local Review Reference can connect this software ticket to outside review material without storing patient name, real MRN, or private identity fields. Empty numeric fields are allowed; invalid numeric text shows a friendly field error and does not run prediction.

Case Safety Profile

The profile shows ICU Stay ID, Subject ID, Hospital Admission ID, source, AI risk/probability, SIRS screening, review priority, status, coordinator, confidence/data quality, model signals, similar cases, cluster context, anomaly detection, uncertainty, notes, and audit trail. It also shows the Recommended Coordinator Action.

AI Risk Engine

This page explains the four layers: the trained Logistic Regression model, the SIRS-style screening baseline, supporting analytics, and the review workflow priority. It also lists what the system does not claim.

Model Validation

Use this page to inspect saved ML metrics, confusion matrices, baseline comparison, precision/recall tradeoffs, and limitations. Do not treat the results as clinical validation.

Dataset Identity and Reproducibility

This workbench uses de-identified ICU stay records. In a real deployment, the hospital would connect the local review reference to its internal EHR identity system.

data/patient_features_ai.csv is the final processed 1000-row feature dataset used at runtime. Earlier patient_features_real.csv was the 100-row development output. Raw MIMIC files are not included.

Source tables documented for preprocessing are PATIENTS.csv, ADMISSIONS.csv, ICUSTAYS.csv, D_ITEMS.csv, D_LABITEMS.csv, CHARTEVENTS.csv, and LABEVENTS.csv. Large tables require chunked reading. Regenerating the dataset may change metrics and requires retraining/retesting.

Installation / Running Instructions

From the parent project folder, enter the software folder, create a virtual environment named .venv, install dependencies, then start the app.

PowerShell:

cd Software_System
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python app.py

Git Bash:

cd Software_System
python -m venv .venv
source .venv/Scripts/activate
pip install -r requirements.txt
python app.py

Open http://127.0.0.1:5000/.
